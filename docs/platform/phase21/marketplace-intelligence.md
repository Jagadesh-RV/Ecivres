# Marketplace Intelligence & Decision Provenance

## 1. Overview
The Marketplace Intelligence Engine provides real-time market-state awareness, liquidity monitoring, pricing surge guardrails, and decision provenance classification across all operating regions.

## 2. Epistemic Signal Classification

To prevent machine-learning approximations or uncertain forecasts from being treated as immutable facts, every intelligence output is categorized:

1. **`FACT`**: Direct, verified observations (e.g. completed booking, settled payment).
2. **`STATISTICAL_ESTIMATE`**: Aggregations computed across verified sample pools (e.g. regional liquidity ratio).
3. **`PREDICTION`**: Probabilistic forecasts generated by ML models (e.g. weekend demand spike).
4. **`RECOMMENDATION`**: Governed policy actions proposed by intelligence agents.
5. **`EXECUTED_ACTION`**: Authoritative changes executed on marketplace state.

## 3. Evidence Sufficiency & Mutation Suppression
`DecisionProvenanceService` enforces safety thresholds before permitting autonomous market interventions:
- Minimum sample size: $\ge 15$ verified transactions.
- Maximum data staleness: $\le 3600\text{s}$ (1 hour).
- If thresholds are breached, status `INSUFFICIENT_DATA` is emitted and state mutations are automatically suppressed.

## 4. Diagnostics Sanitization
Diagnostic logging and provenance evidence payloads are strictly scrubbed to prevent internal LLM system instructions, prompt templates, model weights, or hidden reasoning chains from being exposed in public APIs or audit trails.
