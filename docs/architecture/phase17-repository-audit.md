## 3. Phase 16 Integration Points
Phase 17 builds directly on top of Phase 16 governance and automation infrastructure:
- **Approval Queue**: High-risk actions generated by Phase 17 AI decision engines route through `AutomationApprovalService` (`ApprovalRequest` state machine).
- **Automation Execution Audit**: `AutomationAuditService` logs every agent action and execution result.
- **Anomaly Signals**: Signals from `AnomalyDetectionService` feed directly into `FeatureEngineeringService` for decision scoring.
- **Health Aggregation**: `MarketplaceCommandCenterService` provides real-time system metrics as input features.

## 4. Reusable Infrastructure & Databases
- **Authentication & Security**: `JwtAuthGuard`, `RolesGuard`, `TenantInterceptor`, `RbacPolicy`.
- **Event Bus & Queues**: BullMQ queues with Redis for asynchronous background processing and event handling.
- **Database Models**: Reusing existing `User`, `ProviderProfile`, `CustomerProfile`, `Booking`, `Payment`, `AutomationPolicy`, `ApprovalRequest`, `AnomalyEvent` models.

## 5. Security & RBAC Architecture
- All Phase 17 administrative decision and agent APIs use `@UseGuards(JwtAuthGuard, RolesGuard)` and `@Roles('ADMIN')`.
- Agent tool execution enforces server-side tool permissions (`AGENT_READ_MARKETPLACE`, `AGENT_REQUEST_APPROVAL`, etc.) preventing privilege escalation or unauthorized mutations.

## 6. Identified Gaps for Phase 17
1. **Decision Intelligence Domain**: Lacks canonical `DecisionContext` normalization and multi-factor evidence scoring.
2. **Feature Engineering Layer**: Lacks unified feature extraction across demand, supply, customer, provider, financial, and operational telemetry.
3. **Forecasting Engines**: Requires deterministic moving-average, exponential smoothing, and trend forecasting for demand and revenue horizons (1h, 1d, 7d, 30d).
4. **Marketplace Scenario Simulator**: Needs what-if simulation capabilities for pricing, provider capacity, and promotional adjustments.
5. **Controlled Agent Orchestration**: Lacks a unified agent planner, tool permission registry, and emergency agent kill-switch guardrails.
6. **Continuous Evaluation & Audit**: Lacks AI prediction evaluation metrics (MAE, RMSE, accuracy tracking) and a decision audit ledger.

## 7. Explicit List of Functionality NOT to Duplicate
- **DO NOT RECREATE** Anomaly Detection Engine (extend `AnomalyDetectionService`).
- **DO NOT RECREATE** Automation Policy & Approval Queue (integrate with `AutomationApprovalService`).
- **DO NOT RECREATE** Command Center Health Monitors (reuse `MarketplaceCommandCenterService`).
- **DO NOT RECREATE** Dynamic Pricing Engine (extend existing `commerce-intel` / `pricing` logic).
- **DO NOT RECREATE** Event/Queue Bus (use existing BullMQ Redis infrastructure).

## 8. Phase 17 Target Architecture Proposal
Logical Pipeline:
```
Marketplace Events / Telemetry
  └─► Feature Engineering Layer (Phase 17B)
        ├─► Demand & Revenue Forecasting (Phase 17C/D)
        ├─► Customer & Provider Intelligence (Phase 17E/F)
        ├─► What-If Marketplace Simulator (Phase 17I)
        └─► Decision Engine & Agent Orchestration (Phase 17J/K/L/M/N/O)
              ├─► Risk & Safety Guardrails Check (Phase 17N)
              ├─► Phase 16 Human Approval Queue (if High-Risk)
              ├─► Execution & Idempotent Tool Execution
              └─► Outcome Measurement & Continuous Learning Loop (Phase 17R/S)
```
